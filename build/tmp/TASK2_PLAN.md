# Задача 2: звук игры AY -> ВИ53 (ветка splash, после fc3c9d9)

## Дизайн (решён по разведке 2026-09-22)
- **Мелодии**: отказаться от real-time MSX-пересчёта. Играть `src/msx_tunes_vi53.bin`
  (847 Б, готов; формат: +0 u16 N=6; далее 6 записей (u16 смещение блоба, u16 длина в
  кадрах); блобы = a8_tune_c64 Re-Pair, голос C всегда пуст). Плеер — тот же a8_tv, что
  у заставки (код в tools/a8_vec.py, fc3c9d9), но теперь в ОБЫЧной сборке (не release-only).
  Каналы: AY A -> счётчик 1, AY B -> счётчик 2, счётчик 0 не трогать (секундомер di).
  Играет ровно «длина в кадрах» тиков, потом глушит счётчики 1/2 и возвращает.
- **SFX**: рецепт Knight Lore (kl_sound_ay.py): msx_wr пишет в зеркало msx_ayregs (DS 16)
  вместо портов 0x15/0x14; раз в кадр (точка msx_frame_off, build/alien8_vec.asm:2673)
  msx_viflush: для счётчиков 1,2: канал B->1, C->2; канал A (слот 0) ворует свободный
  (сперва 2, потом 1), третий эффект отбрасывается; делитель = 13P + P/2 (kl-целое);
  громкость: порог 6/15, бит огибающей 0x10 = полный голос; шум R6 -> делитель R6*256;
  делитель < 64 -> тишина; управляющее слово (0x76/0xB6...) только при смене ВЛАДЕЛЬЦА
  (msx_viown), при возврате владельца кэш делителя msx_vidiv = 0xFFFF; тот же делитель —
  не писать; тишина = управляющее слово без делителя; порты: ctrl 0x08, c1=0x0A, c2=0x09
  (порты ПЕРЕСТАВЛЕНЫ!), out (c) нет — заглушка-stub (D3 port C9, ret на +2!).
- Мелодия и SFX не конфликтуют: msx_sfx_start отказывает во время мелодии (как в MSX).
  При старте мелодии: msx_viown[1],msx_viown[2]=0xFF + побить кэши.
- msx_silence/msx_stop (стоп-список AY) -> заглушить счётчики 1,2 тем же способом.
- Мелодия теперь НЕ ходит в vec_isr (голос C пуст) — правки vec_isr для мелодий не нужны.

## Куда положить блоб 847 Б
- INCBIN нет нигде, все данные — DB-строки из build-скриптов. Состояние: нижний регион
  до 0x7700, крупнейший разрыв 0x74DD..0x77FF = 803 Б — мало (нужно 847 + плеер ~430).
- Проверенные варианты: дыра plane 2 0xD9E4..0xDFDF (1532 Б) — но plane 2 читается HUD?
  (il_* пишут в окна 0xC000..0xDFFF; 0xD9E4..0xDFDF помечена свободной в sld, НО это окно
  может писаться HUD во время игры — ПРОВЕРИТЬ у scout: кто пишет 0xD900..0xDFDF).
- Либо: сжать/вынести; либо разбить: мелодии в 0x9000..0x9FFF (не проверен!) — ПРОВЕРИТЬ
  map: 0x8000..0x9FFF = plane 0 (в release — заставка; в обычном билде — что там?).
- Кандидат без новых мест: msx_stream (445 Б) и msx_per удаляются вместе с real-time
  плеером -> освобождаются ~0x471C..0x49B7 (~650 Б) в нижнем регионе; блоб 847 Б влезает
  туда + плеер a8_tv (~430 Б) в освободившееся же. ИТОГО: удалить data_block() из
  a8_sound_ay.py, на его место INCBIN/DB msx_tunes_vi53.bin, код a8_tv перенести из
  release-only в постоянный (он в a8_vec.py рядом с a8_sound_ay-инъекцией).

## Гейты
- aytrace_vec.js: тапать 0x08/0x0B/0x0A/0x09; лог: «V <frame> <counter> <div>» (эффективный
  делитель на конец кадра, реконструкция как в c64tune_vec.js applyTaps) + оставить TUNE/SFX/ITER.
- aycheck.py: сравнение перестроить на «модель msx_psg_model -> конверсия (13.5, порог 6,
  огибающая=полный, R6*256, owner/steal, flush раз в кадр) -> ожидаемые делители по кадрам
  -> сверка с V-строками». Проходы модели: тик SFX = 56/кадр (msx_sfx_rest), не 114.
- tunecheck_vec.js: тапы A8TUNETRACE 0x15/0x14 -> 0x08..0x0B; темп: play_audio теперь
  плеер блоба — длительности заданы в заголовке блоба, модель = длина из заголовка ±0.
- gatecheck.py: гейты tune/sfx остаются по имени, команды поменяются если поменяются аргументы.

## Порядок работ
1. scout: кто пишет 0xD900..0xDFDF в игре; что лежит в 0x8000..0x9FFF обычного vec-билда;
   точные тела msx_fetch/msx_sfx_run mse1..mse9 местами правки (write->зеркало).
2. Правка tools/a8_sound_ay.py: msx_wr -> зеркало; +msx_viflush/vicalc/viwant/viemit (kl);
   точки вызова: msx_frame_off -> flush; play_audio -> плеер блоба.
3. Правка tools/a8_vec.py: a8_tv из release-only -> постоянный; play_audio = инициализация
   проигрывателя по блобу + тик раз в кадр (у мелодий уже есть кадр-цикл msx_frame — тик там).
4. Гейты: aytrace_vec.js, aycheck.py, tunecheck_vec.js.
5. Полный прогон gatecheck.py (27 гейтов), записать новый vec md5 в коммит.

### Сделано с шага WIP (407d88a -> ee34cd4)
- Отладка плеера, три бага (все в tools/a8_sound_ay.py; врезки build/tmp/splice_fix_pc.py,
  splice_fix_rem.py, splice_fix_rem2.py):
  1) msx_play_tune обрезал pc/start обоих голосов до младшего байта: после
     `ld a,d / adc a,b` старший байт абсолютного адреса оставался в A, а store писал D
     (старший байт смещения = 0). Интерпретатор читал токены из нулевой страницы
     (tok@0x4A=0xFF) и крутился tok->0xFF->tv_ret->fin; play_audio не возвращался из
     start_game — гейт «не дошли до комнаты».
  2) 16-битный dec rem в msx_tv_tick занимал у старшего не там: заём нужен при lo==0
     (0->FF), а не при lo=1->0. Мелодии длиннее 255 кадров (game_over 576, menu 1151,
     obj_5C 288) переходили rem за ноль (0x400->0x4FF каждые 256 кадров) и не кончались.
     Теперь: lo>0 -> dec lo; lo==0 -> lo=FF + dec hi. (splice_fix_rem сначала снял заём
     совсем — отменён правильным splice_fix_rem2; у мелодий с lo!=0 ноль достигался
     ровно и эти 3 прошли уже тогда.)
  3) сборка: sjasmplus в 8080-режиме не знает `ora a` — пишем `or a`.
- Гейт tools/tunecheck_vec.js: инвариант счётчика 0 учитывает vec_cu (команда защёлки

### Шаг B (слив эффектов в ВИ53): что подготовлено (2026-09-23, ничего не применено)
Два скрипта врезки (по номерам строк, атомарные; якоря msx_frame_off/добивки — динамические,
порядок запуска ЛЮБОЙ, но каждый ОДИН раз; после обеих — одна сборка):
- build/tmp/splice_B1.py (tools/a8_sound_ay.py, мелкие правки в нижнем регионе):
  msx_wr пишет в зеркало msx_ayregs[C&0x0F] вместо портов 0x15/0x14 (зеркало 16-выровнено);
  msx_wlist удалён; msx_silence = тишина зеркалом (R7=0xFF, громкости 8/9/10=0), таблица
  msx_stop удалена из data_block; msx_frame_off = `ld a,(msx_play); or a; call z, msx_viflush;
  jp msx_silence` (во время мелодии счётчики у неё — flush не трогает); msx_play_tune при
  старте бросает msx_viown[1],[2]=0xFF и msx_vidiv[1],[2]=0xFFFF (плеер мелодий пишет
  счётчики напрямую — иначе первая нота после мелодии «совпадёт с кэшем» и промолчит);
  msx_snd_init заряжает msx_vistub (0xD3/порт/0xC9).
- build/tmp/splice_B2.py: перед msx_frame_off — 5 процедур по KL (kl_sound_ay.py:172-456):
  msx_viflush (раз в кадр: vcalc×3 -> viwant -> viemit×2, беречь BC/DE/HL), msx_vcalc
  (порог 6/15, огибающая 0x10=полный, R7 cpl & msx_kmask, тон: 13P+P/2 через msx_ay2vi,
  только шум: R6&0x1F (0->1)*256, делитель<64 -> тишина), msx_viwant (счётчик 0 не для
  каналов; B->1, C->2; канал A ворует свободный: сперва 2, потом 1; оба заняты — третий
  отброшен), msx_viemit (порт 0x0B-c: 1->0x0A, 2->0x09; ctrl 0x76/0xB6 только при смене
  владельца + бой кэша vidiv=0xFFFF; тот же делитель — не писать; тишина = ctrl БЕЗ
  делителя; запись LSB-first через msx_vistub). Состояние — STATE-блок в добивке:
  ORG 0x7FC0 (0x7FB8 не 16-выровнено), ayregs 16 + viown 3 + vidiv 6 + viw 3 + vact 3 +
  vdiv 6 + vistub 3 + vich 2 = 0x7FC0..0x7FED, ASSERT $ <= 0x7FF6. Раскладка выбрана так,
  что все индексы (viown+2c, vidiv+2c, viw+c, vact+c, vdiv+2C) не дают переноса из
  младшего — адресация `ld l,a / ld h,high` без adc. vhold (отложенная нота KL) НЕ
  перенесён: эффект короче кадра может не быть застигнут ни одним flush.
- НЕ применено и НЕ надо: A8_SP_RESV не трогать (стек не ужимать — записка Spirits).
  Сторож стека только ПОДНЯТЬ до замера: tools/a8_vec.py:1321 `ASSERT seed_1 - 0x7700 >=
  0x40` -> `>= 0x44` (замер spcheck 68 Б; сейчас сторож слабее замера).
- Дефицит места: нижний регион 0x76E5/свободно 27 Б, новый код ~350..450 Б. Решение
